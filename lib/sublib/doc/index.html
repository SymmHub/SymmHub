Quick start

Give it a presentation; it returns the conjugacy classes of subgroups of index ≤ n, each described by the permutations its parent generators induce on the cosets.

Copy the folder and import from src/sublib.js — from a page, from node, or through a bundler. That one module is the whole supported surface.

// the group is given by generators and relators, as text
import { subgroupsData } from './sublib/src/sublib.js';

const data = subgroupsData({
  name:     '2222',
  gens:     'a b c d',
  relators: 'a^2, b^2, c*d, (c*a)^2, (c*b)^2',
  maxIndex: 24,
  maxSubgroups: 1000,          // budget: stop climbing when it is spent
});

data.totalCount;               // 999
data.subgroups[1];
// { subgroup: '2222.2.1', index: 2, generators: 'a b CC',
//   cosets: 'ab ab ba ba', invcos: 'ab ab ba ba' }

The 17 wallpaper groups and the triangle-group families are built in, so most calls are one line:

subgroupsData({ preset: 'wallpaper:*632', maxIndex: 24 });
subgroupsData({ preset: 'klm:237',        maxIndex: 24, maxSubgroups: 300 });
subgroupsData({ preset: '2222',           maxIndex: 12 });   // bare orbifold works too

Relator syntax

Juxtaposition or *; ^n with negative n allowed; parentheses; [a,b] for the commutator a⁻¹b⁻¹ab; uppercase for inverses; and u = v for a relation. Generators are single lowercase letters.

Reading cosets and invcos

These are the payload. Each is a space-separated list of blocks, one block per generator of the parent group, in the order the generators are declared. A block has one character per coset: the character at position i names the coset that coset i is mapped to. cosets holds the generators, invcos their inverses.

Cosets are named from a 62-symbol alphabet — a…z A…Z 0…9 — so coset 0 is a and the largest workable index is 62. To get plain arrays instead:

import { permStringToArrays } from './sublib/src/sublib.js';

permStringToArrays('ab ab ba ba');   // [[0,1], [0,1], [1,0], [1,0]] — 0-based
Watch out

The generators field lists words that generate the subgroup, uppercase meaning inverse — but written right to left, the convention of the GAP exporter that produced the shipped files. Pass generators: 'natural' for un-reversed words, or 'none' to skip them. Coset representatives, below, always read left to right.

Subgroup ids are <name>.<index>.<k>, with k numbering from 1 within each index.

Coset representatives

cosetRepresentatives(data, id) returns the N elements of a transversal of a subgroup of index N — one representative per right coset, as words in the parent generators, the first of them the identity.

import { subgroupsData, cosetRepresentatives } from './sublib/src/sublib.js';

const data = subgroupsData({ preset: 'wallpaper:632', maxIndex: 12 });

cosetRepresentatives(data, '632.6.1').map(r => r.word);
// [ '1', 'b', 'B', 'Ba', 'Bab', 'BaB' ]

This falls straight out of the coset table: generator x sends coset Hg to Hgx, so a word labelling a path from coset 0 to coset i is a representative of coset i. Entry i of the returned array is coset i, so it lines up with position i of every block in cosets.

fieldmeaning
cosetcoset number, 0-based; equals the array position
symbolthe same coset as it appears in cosets / invcos
wordthe representative as text, uppercase for inverses, '1' for the identity
lettersthe same word as signed generator numbers (+k / −k, 1-based)
lengthnumber of letters
via{from, letter, gen} — the single generator reaching this coset from an already-built one; null for coset 0
Read left to right

'Bab' means b⁻¹·a·b, applied in that order. This is the opposite of the generators field; the reversal there is the GAP exporter's, and it stops at this function.

It also accepts a bare subgroup entry, or a position in the list, and it reads generator names from the result's presentation or from its Group( [ … ] ) string — so it works on a JSON file loaded straight from color_groups:

cosetRepresentatives(data, 3);                        // by position
cosetRepresentatives(data.subgroups[3]);              // the entry alone
cosetRepresentatives(entry, { gens: 'x y z' });       // or name the generators

Fundamental domains

This is what turns a fundamental domain for the group into one for the subgroup. If F is a fundamental domain for G acting on the left, and the transversal splits the group into right cosets

G = H t0 ⊔ H t1 ⊔ … ⊔ H tN−1,

then

D = t0·F ∪ t1·F ∪ … ∪ tN−1·F

is a fundamental domain for H — N copies of the group's tile, one per coset, with the identity contributing F itself.

Rather than evaluate each word from scratch, build the tiles in order and use via, which names the single generator that reaches a coset from one already built. Because the transversal is prefix-closed, via.from is always ready before it is needed:

const reps = cosetRepresentatives(data, '632.6.1');
const T = new Array(reps.length);

T[0] = identityTransform();
for (const r of reps.slice(1)) {
  T[r.coset] = compose(T[r.via.from], transformOf(r.via.gen));
}

// tiles: T[i] applied to the group's fundamental domain F

One matrix multiply per tile, and no long products to accumulate error. Neighbours come from the table itself: apply generator g to the tile of coset i and you land on the tile of coset permStringToArrays(entry.cosets)[g][i].

What "canonical" means here

The words come from a breadth-first walk of the coset table in its own scan order — cosets in numerical order, and within a coset the columns g1, g1−1, g2, g2−1, … Three things follow.

  • Each ti is a shortest word reaching coset i, and the first such word in that column order.
  • Being shortest, they are freely reduced — no cancellation to clean up.
  • The set is prefix-closed — a Schreier transversal: every prefix of a representative is itself a representative. That is what makes the via construction above work.

And because the table sublib hands out is the canonical one for its conjugacy class — the lexicographically least over all choices of base point — the transversal depends only on the subgroup, not on how the search happened to find it.

Shortest words also mean compact fundamental domains: the tiles cluster around the group's own tile instead of straggling off in one direction.

Three families are built in, keyed as family:name. Wallpaper groups also answer to their bare orbifold symbol.

import { getPreset, PRESETS, WALLPAPER_NAMES, klmPresentation } from './sublib/src/sublib.js';

getPreset('wallpaper:632');   // { name: '632', family: 'wallpaper', gens: 'a b c', relators: 'a^2, b^3, (a*b)^6, b*c' }
klmPresentation(2, 3, 7);     // { name: '237', family: 'klm', … }
WALLPAPER_NAMES;              // ['o', '2222', '**', 'xx', '*x', '*2222', …]

The presentations are those in sympix's gap/groups_wp.g and gap/groups_klm.g, character for character, so sublib reproduces the shipped files rather than an equivalent-but-different enumeration. Anything you pass explicitly wins over the preset, so { preset: 'klm:237', name: 'hurwitz' } relabels the same group.

One caveat

The 3*3 presentation carries a WRONG comment in the GAP source. sublib keeps it verbatim — see the note field on that preset — rather than silently substituting a different group.

Using it in sympix

apps/sympix/js/Subgroups.js fetches a JSON file and hands it to parseSubgroupsData(data, name, preferredSubgroup). sublib produces the same object, so computing replaces fetching:

import { subgroupsData, getPreset } from './sublib/src/sublib.js';

// instead of: const data = await (await fetch(url)).json();
const data = subgroupsData({ preset: 'wallpaper:2222', maxIndex: 24, maxSubgroups: 1000 });
parseSubgroupsData(data, 'sublib:wallpaper:2222', preferredSubgroup);

Everything downstream works unchanged — the index chips built from countPerIndex, the subgroup list, the normalizePerms(s.invcos) === parentPerms lookup.

For that last lookup, findByPermutations is more forgiving than an exact string compare: with { upToConjugacy: true } it finds the class even when the permutations came from a different — but conjugate — representative, such as one of the pre-generated files.

findByPermutations(data, parentPerms, { upToConjugacy: true });
Ids are not portable

The k in 2222.6.13 is sublib's own numbering. GAP's within-index order came from its search order passed through an unstable sort and is not reproducible, so a saved id may name a different subgroup in a pre-generated file. Match on permutations, not on ids, when both sources are in play.

Long searches block

Everything runs synchronously on the calling thread. For interactive use, bound it with deadlineMs — the result then carries data.stats.aborted === true and is incomplete — or run the module in a Worker.

Agreement with GAP

sublib is checked file by file against the corpus GAP produced for sympix: 17 wallpaper files, 343 klm, 343 *klm. For every one of the 703 it recomputes the enumeration from the presentation recorded in that file and compares. All 703 pass.

familyfilessubgroupspermutations identical to GAP
wallpaper174 8474 847 · 100%
*klm34354 69154 691 · 100%
klm34350 98647 739 · 93.6%
  • countPerIndex, maxIndex, nextIndex, nextIndexCount and totalCount are identical everywhere — the budget walk reproduces GAP's findMaxIndex exactly.
  • Every subgroup in every GAP file is in exactly one of sublib's classes, matched by canonical form: the two enumerations agree as sets of conjugacy classes.
  • Where the permutations differ, sublib and GAP picked different representatives of the same class, so the two permutation sets are relabelings of each other. sublib picks the lexicographically least standardized table, which is canonical and independent of search order; GAP returns whichever representative its backtrack happened to accept.
node test/smoke.mjs                                 # no corpus needed
node test/validate-corpus.mjs --family wallpaper    # 17 files, ~2 s
node test/validate-corpus.mjs --family sklm         # 343 files, ~4 min
node test/validate-corpus.mjs --family klm          # 343 files, ~25 min

The smoke suite needs no corpus. It checks σ(n) for ℤ², Marshall Hall's subgroup counts for the free group of rank 2, GAP's published class counts for the (2,3,7) and *283 triangle groups, the 62-symbol alphabet, the budget walk, the transversal properties above, and that pruning the search changes nothing about its answer.

Performance

Single-threaded, on the corpus presentations to index 24: the 17 wallpaper groups take 5–290 ms each (2222, the largest at 999 subgroups, is 290 ms). Triangle groups are the expensive end — most *klm groups are under a second, while the hardest klm ones take around 30 s.

Two things do the work. The search prunes non-canonical branches as it goes, so it builds one table per conjugacy class instead of one per subgroup — 3–8× fewer search nodes. And with a maxSubgroups budget it climbs one index at a time and stops as soon as the budget is spent, rather than enumerating to maxIndex and discarding the excess. On klm:346 that second point alone is 32 ms instead of 14 s.

A budget is the cheapest bound

Cost grows steeply with the index. If you only need a few hundred subgroups, saying so with maxSubgroups is far better than lowering maxIndex and guessing.

How it works

A Sims-style low-index backtrack over coset tables: extend a partial table at its first undefined entry, propagate the consequences of every relator, and record each table that comes out complete on ≤ maxIndex cosets. Complete standardized tables are in bijection with the subgroups of that index, and restandardizing one from a different base point gives the table of a conjugate subgroup — so the least table over all base points identifies the conjugacy class, which is what GAP's LowIndexSubgroupsFpGroup returns.

Rather than build every subgroup and group them afterwards, the search carries Sims' canonicity test: at each node it compares the table with its restandardizations and abandons the branch as soon as one of them is strictly smaller over the entries defined so far. A prefix that already loses still loses however it is completed, so nothing canonical is ever discarded, and what survives to completion is exactly one table per class. The class size is then recovered from the representative alone, as the number of distinct restandardizations.

The coset-table conventions match GAP's: cosets are numbered in the order they are first reached, scanning rows in order and, within a row, columns in the order g1, g1−1, g2, g2−1, … That is why the permutation strings agree with GAP's verbatim rather than merely up to relabeling.

Pass prune: false to subgroupClasses to switch the test off and enumerate every subgroup instead; the classes that come out are identical, which the smoke suite checks group by group.

verifyData(data) re-checks a result from scratch: every block a permutation, invcos inverting cosets, every relator acting trivially on the cosets, and every listed generator word stabilizing coset 0.
